# Claude Code に最初に渡すプロンプト

このフォルダ(`todo-app/`)を Claude Code で開き、下の枠の中をそのまま貼る。

```text
このフォルダは、Tauri 2 で作るTODO管理デスクトップアプリのプロジェクトです。要件・設計・画面モックは確定済みで、docs/ に入っています。MVPの実装をお願いします。

まず、次の順に読んでください。
1. CLAUDE.md
2. docs/README.md(資料の一覧と優先順位)
3. docs/requirements-design.md(要件と設計の全文)
4. docs/implementation-plan.md(フェーズ分けと完了条件)
5. docs/ui-mock/README.md と docs/ui-mock/screenshots/(画面の見た目)

読み終えたら、コードを書く前に次の3点を報告してください。
- 開発環境の確認結果(OS、Rust、Node.js、Tauri 2 の前提条件)。足りないものがあれば、入れ方を案内してください。
- 資料を読んで見つけた矛盾や、実装の前に決めておくべき点。なければ「なし」で構いません。
- フェーズ0とフェーズ1の作業計画。

私が計画を承認したら、フェーズ0とフェーズ1を実装してください。フェーズ1が終わったら、テスト結果と次のフェーズの計画を報告して止まってください。

進め方の決めごとです。
- ライブラリのバージョンは記憶に頼らず、導入時点の最新安定版と互換性を確認して使ってください。
- 設計書と違う実装にしたい場合や、設計書にない判断が必要な場合は、理由と選択肢を添えて先に相談してください。
- 設計書の「未決事項」は、書いてある仮定のまま進めてください。
- フェーズごとにコミットしてください。
```

## 2回目以降の例

フェーズの報告を確認したあとは、短い指示で進められる。

```text
フェーズ1を確認しました。フェーズ2と3を進めてください。終わったら、画面で確認する手順を教えてください。
```

画面を見て直したい点が出たときは、どの画面のどこが、モックのどのキャプチャと違うかを伝える。

```text
TODO一覧の日限の列が docs/ui-mock/screenshots/3-todos-list.png と違います。日付の下に区分(「今日が日限」「あと1日」)が出ていません。直してください。
```
