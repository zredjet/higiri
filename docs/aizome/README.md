Aizome は、濃い藍色を軸にした SaaS / Web アプリのためのデザインシステム。藍染が浅葱から褐色まで染め重ねで深くなるように、淡い藍から濃い藍までの一本の色相で画面を組み立てる。静かで、精確で、迷わせない UI を目指す。

## 原則

- **藍は一つの場所に集める。** 濃い藍(`primary`、`nav-bg`)は「ここが主役」という場所にだけ置く。主要ボタンは1画面に1つ、サイドナビは常に藍。それ以外は墨(`sumi`)の無彩色で静かに保つ。
- **線で区切り、影で浮かせる。** 置かれている面(カード、テーブル)は `border` の 1px 線で区切る。影は浮いている面(メニュー、ダイアログ)にだけ使う。
- **色だけで意味を伝えない。** 状態は必ず語かアイコンを添える(`Badge` の語、`Alert` のアイコン)。
- **数字は揃える。** 金額・件数・日付は半角、表では右寄せの等幅数字(`font-variant-numeric: tabular-nums`)。

## 文章の基本

- です・ます調。短く、主語より結果を先に。「保存しました」「招待を送信しました」。
- ボタンは動詞で終わる短い語:「保存」「招待を送信」「削除する」。確認ダイアログの主操作は具体的な動詞にする(「OK」「はい」は使わない)。
- エラーは「何が起きたか」+「どうすればよいか」:「カードの有効期限が切れています。支払い方法を更新してください。」 利用者を責める言い方(「〜が間違っています」)はしない。
- 英数字は半角。日付は表では `2026/10/31`、文中では「10月31日」。金額は `¥248,000`、税込・税抜は見出しに書く(「金額(税込)」)。
- 「!」と絵文字は使わない。カタカナ語は一般的な表記に揃える(「メンバー」「ユーザー」)。
- 空状態は事実+次の一手:「該当する請求書はありません。条件を変えて検索してください。」

## 色

色は二層。**セマンティックトークン**(`bg`、`text`、`primary` など)をコンポーネントと画面で使い、テーマで値が切り替わる。**原色パレット**(`ai-*` 藍、`sumi-*` 墨、`midori-*` 緑、`kohaku-*` 琥珀、`shu-*` 朱)は両テーマ共通で、グラフやイラストにだけ直接使う。

- **地と面** — ページは `bg`、カードと入力欄は `surface`、浮く面は `surface-raised`、沈む面(テーブル見出し、コード)は `bg-subtle`。ホバーは `surface-hover`。
- **文字** — 本文は `text`、補足は `text-muted`、プレースホルダーは `text-subtle`(`surface` 上でのみ)。無効は `text-disabled`(情報を載せない)。
- **藍** — 主要操作の塗りは `primary`、その上の文字は `on-primary`(ダークでは濃い藍になるので白に固定しない)。藍の文字・リンク・選択中タブは `primary-text`、選択行や info の地は `primary-soft`。
- **サイドナビ** — `nav-bg` はライトでも濃い藍(`ai-900`)、ダークではさらに深い `sumi-975`。項目は `nav-text`、見出しとアイコンは `nav-text-muted`、選択中は `nav-active`。
- **状態** — 成功 `success`(青寄りの緑)、注意 `warning`(琥珀)、エラー・破壊的操作 `danger`(朱)。地は各 `*-soft`。info は藍(`primary-text` / `primary-soft`)を使う。
- **線** — 装飾の区切りは `border`、操作要素の枠は `border-strong`(面に対して 3:1 以上)。
- **スクリム** — ダイアログの背後は `overlay`。

文字色のトークンは、usage に書いた面の上で両テーマとも 4.5:1 以上、`border-strong` と `focus` は 3:1 以上を確認済み。新しい組み合わせを作るときも同じ基準を守る。

## タイポグラフィ

- 書体は **IBM Plex Sans JP**(`--font-sans`)、コードと ID は **IBM Plex Mono**(`--font-mono`)。どちらも Google Fonts から読み込む。読み込めない環境ではヒラギノ角ゴ / Noto Sans JP / 游ゴシック UI にフォールバックする。
- UI の既定は `body`(14px / 22px)。ラベル・ボタン・タブは `label`(14px / 500)。補足は `caption`(12px)。読ませる長文だけ `body-lg`(16px / 28px)。
- 見出しは `h1`(ページタイトル)→ `h2`(セクション、ダイアログ)→ `h3`(カード)。`display` は主要数値や空状態に1画面1つまで。
- 和文に負の字間をかけない。斜体は使わない(強調は 600 の太さで)。行長は全角 35〜40 字程度まで。
- 各スタイルはクラス(`.body`、`.h1` など)としても使える。

## 余白・サイズ・レイアウト

- 4px グリッド。部品の内側は `space-1`〜`space-3`、部品同士は `space-2`〜`space-4`、カードのパディングは `space-5`、カード同士は `space-6`、ページの左右余白は `space-8`。
- 操作要素の高さは `control-md`(36px)が既定。テーブル内・ツールバーは `control-sm`(28px)、ログインやタッチ主体の画面は `control-lg`(44px)。同じ行に並ぶ要素は高さを揃える。
- アプリの骨格は「左にサイドナビ(`sidenav-width` 240px)+ 右にコンテンツ(最大 `content-max` 1200px)」。コンテンツの最上部にページタイトル(`h1`)、その右に主要ボタン。
- 重なり順は `z-sticky` → `z-dropdown` → `z-overlay` → `z-toast` だけを使う。

## 角丸・線・影

- 角は小さく。`radius-sm`(4px)はチェックボックス・バッジ、`radius-md`(6px)はボタン・入力欄・ナビ項目、`radius-lg`(10px)はカード・アラート・ダイアログ。丸いのはスイッチと件数表示だけ(`radius-full`)。
- 影は `shadow-md`(メニュー、ポップオーバー、トースト)と `shadow-lg`(ダイアログ)。`shadow-sm` は押せるカードのホバーとドラッグ中の行だけ。
- 左端に色の帯を付けたカード、グラデーション、すりガラスは使わない。

## 状態とフォーカス

- ホバーは一段明るく/沈める(`primary-hover`、`surface-hover`)。押下は `primary-active`。
- 無効は `bg-subtle` の地と `text-disabled`。無効にする理由は近くに書く。
- キーボードフォーカスは `focus-ring`:2px の地色の隙間、続いて 2px の `focus`(ライト `ai-500`、ダーク `ai-300`)。`:focus-visible` でだけ出し、すべての操作要素に付ける。サイドナビの中だけは `nav-text` 色の 2px アウトライン。
- 動きは 120〜150ms の ease で、色と位置だけ。`prefers-reduced-motion` では止める。

## アイコン

- `Icon` コンポーネントの内蔵セット(24px グリッド、線幅 1.75、丸い線端、`currentColor`)を使う。大きさは小さい操作要素とフィールド内で 16、ボタンとナビで 18、単独で 20。
- 内蔵セットにない形は、同じ線幅・線端の線画で足す。外部ライブラリから補うなら Lucide が最も近いが、線幅を 1.75 に合わせること。
- 塗りのアイコンと絵文字は使わない。アイコンだけのボタンには `aria-label` を必ず付ける。

## ロゴ

ロゴやシンボルマークはまだない。プロダクト名は `--font-sans` の 600 でプレーンに組む(`SideNav` の `header` を参照)。ロゴを作ったら Logos のアセットグループに追加する。

## テーマ

ライト(`light`、既定)とダーク(`dark`)。ルート要素に `data-theme="dark"` を付けると切り替わる。ダークは黒ではなく藍を含んだ墨(`sumi-950`)の地で、藍の主要色は明るい `ai-300` に反転し、その上の文字は濃い藍(`on-primary`)になる。

## コンポーネントの使い方

React 18 を読み込んだページで、`tokens.css`、`components/bundle.css`、`components/bundle.js` の順に読み込む。コンポーネントは `window.Aizome`(`Aizome.Button` など)にある。各コンポーネントの README に、利用側が渡すものと Do / Don't をまとめている。
