# 画面モック

claude.ai 上の「TODO管理アプリ UIデザイン」に描いた6枚の写し(2026-11-19 時点)。Aizome のトークンと部品だけで組んである。

## 使い方

- **見た目を知りたいとき**は `screenshots/` を見る。
- **正確な値を知りたいとき**(余白、幅、色のトークン、文言、表の列)は `.dc.html` を読む。
- `.dc.html` は claude.ai のデザインキャンバス用の形式で、単体では表示できない(`support.js` と `ds/` 以下はキャンバス側にある)。動かそうとせず、仕様として読む。

| 画面 | ソース | キャプチャ |
| --- | --- | --- |
| 1. ダッシュボード | `Main.dc.html` | `1-dashboard-top.png` `1-dashboard-bottom.png` |
| 2. 起動時リマインド | `Reminder.dc.html` | `2-reminder.png` |
| 3. TODO一覧と詳細パネル | `Todos.dc.html` | `3-todos-list.png` `3-todos-detail.png` |
| 4. ガントチャート | `Gantt.dc.html` | `4-gantt-top.png` `4-gantt-bottom.png` |
| 5. 日報 | `Report.dc.html` | `5-report-top.png` `5-report-bottom.png` |
| 6. 設定 | `Settings.dc.html` | `6-settings.png` |

どの画面も幅1440pxで描いた。キャプチャはブラウザで拡大して撮った部分図で、画面全体が1枚に入っていないものがある。`3-todos-list.png` は一覧側、`3-todos-detail.png` は右の詳細パネル側。

## .dc.html の読み方

| 書き方 | 意味 |
| --- | --- |
| `<x-import component-from-global-scope="Aizome.Button" variant="primary" icon-start="plus">TODOを追加</x-import>` | Aizome の部品。`<Button variant="primary" iconStart="plus">TODOを追加</Button>` と同じ。属性はケバブケースで書いてあるので、props ではキャメルケースに読み替える |
| `{{navSections}}` | ファイル末尾の `<script type="text/x-dc">` にある `renderVals()` が返す値。表の列定義やサンプルデータはここにある |
| `<dc-import name="Main">` | 別のモックをそのまま埋め込む。リマインドはダッシュボードの上にダイアログを重ねている |
| `<helmet>` | `<head>` に足す内容 |
| `style="… var(--space-5) …"` | Aizome のトークン。値は `../aizome/tokens.css` |

`renderVals()` の中で `h(A.Badge, { tone, dot: true }, '超過')` のように書いてある箇所は、表のセルに部品を入れている(`h` は `React.createElement`、`A` は `window.Aizome`)。

## 共通の骨格

- 左に `SideNav`(幅240px)、右にコンテンツ。ページの上端にタイトル(h1)、その右に主要ボタンを1つ。
- サイドナビは3つのかたまり。上から、画面(ダッシュボード、TODO、ガント、日報)、プロジェクトの一覧、設定。ダッシュボードには日限注意の合計、各プロジェクトにはそのプロジェクトの日限注意の件数をバッジで出す。
- TODO詳細は右側のパネル(最大幅440px)で、一覧やガントの横に開く。

## ステータスと区分の色

| 表示 | Badge の tone |
| --- | --- |
| 未着手、保留、中止、着手遅れ | `neutral` |
| 作業中、間近 | `primary` |
| 待ち、本日、要確認 | `warning` |
| 完了 | `success` |
| 超過 | `danger` |

すべてドットつき(`dot`)で、名前を文字で添える。

## ガントの寸法

モックでは棒を絶対配置の `div` で置いているが、実装は設計書どおり SVG で、日付から座標を計算する。寸法はモックの値を使う。

- 左の名前列は302px。ヘッダーは53px、プロジェクト行は32px、TODO行は44px。
- 予定の棒は高さ10pxで `--ai-200`、実績の棒は高さ12pxで `--ai-600`。待ちの区間は `--ai-600` の2px枠で中を `--surface` にする。
- TODO行の中で、予定の棒は上から9px、実績の棒は上から23pxの位置に置く。
- 日限は12pxのひし形(`--text` の塗りに、地色の2px縁)。今日は `--primary-text` の2px縦線。
- 1日の幅は、日表示32px、週表示12px、月表示4px(設計書)。

## モックにないもの

静止画なので、次のものは設計書から起こす。

- ステータスを変えるときの入力(待ちにするときの相手と確認日、中止にするときの理由)。`Todos.dc.html` の詳細パネルに「待っている相手」「確認日」の欄はあるが、中止の理由を入れるダイアログは描いていない。
- プロジェクトの作成・編集・アーカイブ・削除の画面。
- 空の状態(TODOが0件、日限注意が0件、保存済みの日報がない日)。文言は Aizome の方針どおり「事実+次の一手」で書く。
- エラー表示、削除の確認、ダークテーマでの見え方。
- 設定画面の「バックアップから復元」を押した先(バックアップの一覧と、復元の確認)。

## サンプルデータ

モックは「今日 = 2026-11-19(木)」として、3プロジェクト・11件のTODOで描いている。開発用のサンプル投入とテストのフィクスチャに使える。投入するときは、今日からの相対日付に直すと区分が保たれる。

| --- | --- | --- | --- | --- | --- | --- |
| 基幹システム更改 | 移行手順書のドラフト | 作業中 | 11/19 | 11/11〜11/18 | 11/12〜 | 本日 |
| 基幹システム更改 | API設計書のレビュー対応(優先度 高) | 待ち | 11/20 | 11/16〜11/19 | 11/17〜 | 間近 |
| 基幹システム更改 | 結合テスト計画の作成 | 未着手 | 11/30 | 11/20〜11/27 | なし | なし |
| 基幹システム更改 | 性能試験の環境準備 | 未着手 | 12/4 | 11/17〜11/20 | なし | 着手遅れ |
| 基幹システム更改 | 要件定義書の改訂 | 完了 | 11/13 | 11/9〜11/13 | 11/10〜11/13 | 対象外 |
| 基幹システム更改 | 旧帳票の移行検証 | 中止(11/19) | 11/27 | 11/24〜11/26 | なし | 対象外 |
| 社内ツール整備 | ライセンス棚卸し | 未着手 | 11/17 | 11/12〜11/13 | なし | 超過(2日) |
| 社内ツール整備 | デプロイ手順書の更新 | 完了(11/19) | 11/24 | 11/18〜11/19 | 11/18〜11/19 | 対象外 |
| 社内ツール整備 | 監視ダッシュボードの整理 | 保留 | 12/3 | 11/24〜11/27 | なし | なし |
| 採用サイト改修 | 募集要項ページの原稿確認 | 待ち | 11/27 | 11/16〜11/20 | 11/16〜 | 要確認 |

- API設計書のレビュー対応は、認証担当の回答待ち。待ち開始 11/19、確認日 11/20。
- 募集要項ページの原稿確認は、人事部の原稿確認待ち。待ち開始 11/17、確認日 11/19。
- 旧帳票の移行検証の中止理由は「旧帳票の廃止が決まったため」。
- 日付は `Gantt.dc.html` の各行の `aria-label` と同じ値(ガントに出していない旧帳票の移行検証だけは `Todos.dc.html` の一覧の値)。優先度は、API設計書のレビュー対応が高、それ以外はモックに出していない(既定の中でよい)。
- この状態での集計は、日限注意5件(超過1、本日1、間近1、要確認1、着手遅れ1)、プロジェクト別の日限注意は3 / 1 / 1、進捗は1/5、1/3、0/2(中止は分母から除く)。
- この日の日報の出力例は `../requirements-design.md` の「日報の生成」にある。
